# Lirnyk — Design Spec

Date: 2026-10-07
Status: Draft for review

## 1. Purpose

Lirnyk is a macOS menu-bar utility that rephrases the currently selected text in any
application using an LLM. The user presses a global hotkey bound to a *profile*; Lirnyk
reads the selection, sends it to the AI with the profile's prompt, and replaces the
selection with the result.

Primary user: the author (personal productivity), distributed as a notarized DMG so it can
be shared with others.

### Success criteria

- Pressing a profile hotkey over selected text in TextEdit, Notes, Mail, Safari, Chrome and
  Slack replaces the selection with the AI result.
- ⌘Z in the target app undoes the replacement.
- The user's clipboard contents are the same before and after a rephrase.
- The app starts at login, lives only in the menu bar, and is configurable from a Settings
  window.
- A notarized, stapled DMG can be produced with one script.

## 2. Decisions (from brainstorming)

| Topic | Decision |
|---|---|
| Text capture | Clipboard only: simulated ⌘C to read, ⌘V to write. No Accessibility-API read/write. |
| Apply mode | Replace directly, no preview. |
| AI provider | OpenRouter only. |
| Model | One global model ID for all profiles. |
| System prompt | Profile prompt is the entire system prompt — no hidden wrapper. |
| Language | Controlled entirely by the profile prompt. |
| Progress feedback | Animated menu-bar icon **and** a small HUD near the mouse cursor. |
| Cancel | Esc while a request is in flight. |
| Focus moved during request | Re-activate the original app, then paste. |
| Nothing selected | Show error in HUD; do nothing else. |
| Clipboard | Save before ⌘C, restore after ⌘V. Lirnyk's own writes marked transient. |
| Hotkey recording | `sindresorhus/KeyboardShortcuts` SPM package. |
| Menu contents | Profiles (with shortcuts, clickable), Settings…, Quit. |
| Min macOS | 14.0 (Sonoma). |
| Distribution | `make install` for local dev; `scripts/release.sh` for Developer ID signed, notarized, stapled DMG. |

## 3. Architecture

Swift 6, SwiftUI app with an AppKit bridge where needed. Xcode project generated by
XcodeGen (`project.yml`). `LSUIElement = YES` (no Dock icon). Not sandboxed (needs
Accessibility to post keyboard events). Hardened Runtime enabled (required for notarization).
Bundle ID: `com.metajourney.lirnyk`.

```
Lirnyk/
  App/
    LirnykApp.swift          @main; MenuBarExtra scene + AppDelegate that wires dependencies
    AppState.swift           @Observable: busy flag + menu-bar icon pulse frame
  Model/
    Profile.swift            struct Profile: Codable, Identifiable {id, title, prompt}
    ProfileStore.swift       @Observable; load/save JSON; seed defaults; CRUD
    SettingsStore.swift      model ID (UserDefaults), API key (Keychain), launch-at-login
    Keychain.swift           minimal generic-password wrapper
  Services/
    RephraseClient.swift     protocol RephraseClient { func rephrase(text:, systemPrompt:) async throws -> String }
    OpenRouterClient.swift   URLSession implementation
    SelectionService.swift   protocol + clipboard implementation (read/replace, clipboard save/restore)
    KeyEventPoster.swift     CGEvent ⌘C / ⌘V posting; wait-for-modifiers-released
    HotkeyManager.swift      registers KeyboardShortcuts per profile; routes to coordinator
    PermissionsService.swift AXIsProcessTrusted check/prompt; open System Settings
    LaunchAtLogin.swift      SMAppService.mainApp wrapper
  Coordinator/
    RephraseCoordinator.swift orchestrates one rephrase job; cancellation; errors
  UI/
    MenuContent.swift        menu-bar dropdown
    HUDPanel.swift           non-activating NSPanel near cursor
    SettingsView.swift       TabView: General, Profiles
    SettingsWindowController.swift  own NSWindow hosting SettingsView (SwiftUI Settings scene cannot be opened programmatically on macOS 14)
    GeneralSettingsView.swift
    ProfilesSettingsView.swift
LirnykTests/
  OpenRouterClientTests.swift
  ProfileStoreTests.swift
  RephraseCoordinatorTests.swift
```

Each unit depends only on protocols of the units below it, so the coordinator is testable
with fakes.

## 4. Components

### 4.1 Profile & ProfileStore
- `Profile { id: UUID, title: String, prompt: String }`. The hotkey is **not** stored in the
  profile; it's stored by KeyboardShortcuts under the name `profile_<uuid>` (KeyboardShortcuts names must not contain dots).
- Persisted at `~/Library/Application Support/Lirnyk/profiles.json` (atomic writes).
- First launch (file absent) seeds:
  - **Friendly** — ⌃⌥F — "Fix typos and grammar. Make the text more friendly and warm. Emoji are allowed where natural. Keep the original language. Output only the rewritten text."
  - **Corporate** — ⌃⌥H — "Fix typos and grammar. Be polite and professional, follow corporate communication style. Keep the original language. Output only the rewritten text."
  - **Tech** — ⌃⌥O — "Rewrite following ASD-STE100 Simplified Technical English. Be concise and direct, no filler. Fix typos. Output only the rewritten text."
  (⌃⌥ instead of ⌘⇧ to avoid clashing with common app shortcuts; user can change.)
- Deleting a profile resets its shortcut name.

### 4.2 SettingsStore
- `modelID: String` in UserDefaults, default `openai/gpt-4o-mini`.
- `apiKey: String?` in Keychain (service `com.metajourney.lirnyk`, account `openrouter`).
- `launchAtLogin: Bool` proxied to `SMAppService.mainApp` status. Enabled on first run.

### 4.3 OpenRouterClient
- `POST https://openrouter.ai/api/v1/chat/completions`
- Headers: `Authorization: Bearer <key>`, `Content-Type: application/json`, `X-Title: Lirnyk`.
- Body: `{ "model": modelID, "messages": [ {role: system, content: profile.prompt}, {role: user, content: text} ] }`, no streaming.
- Timeout 30 s. Response: `choices[0].message.content`, trimmed of leading/trailing whitespace/newlines.
- Errors mapped to `RephraseError`: `missingAPIKey`, `unauthorized` (401), `insufficientCredits` (402),
  `rateLimited` (429), `server(status, message)`, `timeout`, `emptyResponse`, `network(underlying)`.
  OpenRouter `error.message` from JSON body included when present.
- `URLSession` injected so tests can use a `URLProtocol` stub.

### 4.4 SelectionService (clipboard implementation)
`readSelection() async throws -> String`
1. Wait until no modifier keys are physically held (poll `CGEventSource.flagsState(.combinedSessionState)` every 10 ms, max 1 s) so ⌘C is not received as e.g. ⌘⇧C.
2. Snapshot the general pasteboard: all items with all their types' data.
3. Clear pasteboard; remember `changeCount`.
4. Post ⌘C (CGEvent, flags = `.maskCommand` only, posted to `.cghidEventTap`).
5. Poll `changeCount` every 20 ms up to 600 ms. No change or no string → restore snapshot, throw `nothingSelected`.
6. Return the string (snapshot is kept for restore later).

`replaceSelection(with: String) async`
1. Write result to pasteboard as `.string` plus marker type `org.nspasteboard.TransientType`.
2. Post ⌘V.
3. After 1 s restore the snapshot — unless the user copied something since the read, in which case their new clipboard is kept.

`restoreClipboard()` — used on cancel/error paths after a successful read.

### 4.5 HotkeyManager
- Observes ProfileStore; for each profile calls `KeyboardShortcuts.onKeyUp(for: .init("profile_\(id)"))` → `coordinator.run(profile)`. Re-syncs on profile add/delete (removes handlers of deleted profiles).
- Uses key-*up* to reduce the chance modifiers are still held.

### 4.6 RephraseCoordinator (`@MainActor`)
`run(profile)`:
1. If a job is running → ignore (HUD flashes "Busy").
2. Preconditions: Accessibility trusted (else HUD error + open Settings), API key present.
3. Record `NSWorkspace.shared.frontmostApplication` as `originApp`.
4. `readSelection()` → on `nothingSelected` HUD error "Nothing selected".
5. `AppState.busy = profile`; HUD shows "✦ <title>… esc to cancel"; menu icon animates.
6. Install global + local Esc key monitor → cancels the task.
7. `client.rephrase(...)`.
8. On success: if frontmost app ≠ originApp → `originApp.activate()`, wait 200 ms. If the origin app still isn't frontmost after ~1 s, don't paste: leave the result on the clipboard and show "Couldn't return to the original app — result copied". Then `replaceSelection(Whitespace.preserving(of: original, in: result))` — the result is trimmed and the original selection's leading/trailing whitespace (e.g. the newline a triple-click selects) is re-applied.
9. On error/cancel: `restoreClipboard()`, HUD error for 3 s (cancel: "Cancelled", 1 s).
10. Always: remove Esc monitor, clear busy state.

The menu "run profile" action waits 300 ms after the menu closes before calling `run`, so the
previous app regains focus.

### 4.7 Feedback UI
- **Menu-bar icon**: SF Symbol `text.quote` normally; while busy, cycles a pulse animation (`symbolEffect(.pulse)` or alternating symbol via timer).
- **HUDPanel**: borderless, non-activating `NSPanel`, `.floating` level, joins all spaces, ignores mouse. Positioned 16 pt below-right of the mouse location, clamped to the screen's visible frame. Capsule with `.regularMaterial`. States: working (spinner + text), error (red icon + message, auto-hide 3 s).

### 4.8 Settings window
- **General**: Accessibility status (green check or warning + "Open System Settings" button, refreshed on window focus); OpenRouter API key (`SecureField`, saved to Keychain on commit); Model ID text field with link to openrouter.ai/models; Launch at login toggle; "Test connection" button (sends "ping" with system prompt "Reply with OK" and shows result/error).
- **Profiles**: `NavigationSplitView`-style list (+ / − buttons) and detail with Title `TextField`, `KeyboardShortcuts.Recorder`, Prompt `TextEditor`. Changes saved to disk on every edit (file is tiny).

### 4.9 Menu
```
Friendly            ⌃⌥F
Corporate           ⌃⌥H
Tech                ⌃⌥O
─────────────
⚠ Grant Accessibility…   (only when not trusted)
Settings…           ⌘,
Quit Lirnyk         ⌘Q
```

## 5. Error handling summary

| Situation | Behaviour |
|---|---|
| Accessibility not granted | HUD "Accessibility permission required"; Settings opened at General. |
| No API key | HUD "Set your OpenRouter API key in Settings"; Settings opened. |
| Nothing selected | HUD "Nothing selected"; clipboard restored. |
| 401 / 402 / 429 / 5xx / timeout / network | HUD with mapped message; clipboard restored. |
| Empty AI response | HUD "AI returned empty text"; selection untouched. |
| Esc pressed | Request cancelled; HUD "Cancelled"; clipboard restored. |
| Hotkey while busy | Ignored; HUD "Busy". |

## 6. Testing

Automated (Swift Testing, `xcodebuild test`, hosted in the app; app skips startup when running under tests):
- `OpenRouterClientTests`: request shape (URL, headers, body), success parsing and trimming, each HTTP error mapping, empty content → `emptyResponse`, missing key.
- `ProfileStoreTests`: seeding on first launch, save/load round trip, add/delete, corrupt file → reseeds without crashing (backs up corrupt file).
- `RephraseCoordinatorTests` (fake SelectionService, fake RephraseClient, fake permission/frontmost providers): happy path calls replace with result; nothing-selected path; error path restores clipboard and doesn't replace; cancel path; busy re-entry ignored.

Manual checklist (documented in `docs/manual-test.md`): TextEdit, Notes, Mail, Safari textarea, Chrome textarea, Slack message box, VS Code; ⌘Z undo; clipboard preserved; focus-switch during request; Esc cancel; launch at login after reboot.

## 7. Build & release

- `project.yml` (XcodeGen): app target + unit-test target, SPM dependency `KeyboardShortcuts` (from 2.0.0), deployment target 14.0, hardened runtime, `LSUIElement`, `NSAppleEventsUsageDescription` not needed.
- `Makefile`:
  - `make project` → `xcodegen generate`
  - `make build` / `make test`
  - `make install` → Release build signed with "Apple Development", copied to `/Applications/Lirnyk.app`, relaunched.
- `scripts/release.sh`:
  1. `xcodebuild archive` (Release).
  2. `xcodebuild -exportArchive` with `ExportOptions.plist` (`method = developer-id`).
  3. `xcrun notarytool submit --keychain-profile lirnyk-notary --wait` on zipped app; `xcrun stapler staple`.
  4. Create DMG with `hdiutil` (app + /Applications symlink), sign DMG, notarize + staple DMG.
  5. Output `build/Lirnyk-<version>.dmg`.
  - Prerequisites documented in README: Developer ID Application certificate in keychain; `xcrun notarytool store-credentials lirnyk-notary`.

## 8. Out of scope (v1)

Other AI providers; per-profile models; streaming output; preview window; history; Accessibility-API
text reading; auto-update (Sparkle); localization of the UI.
